## Immediate implementation order
### 1. Harvest and preserve
For each accessible repository, collect default branch, head commit, README, license, language/build files, test commands, workflow definitions, package entry points, and artifact links. Record private/unavailable nodes as ACCESS_BLOCKED, not absent. Store source snapshot digests without overwriting originals.

### 2. Build a canonical module catalog
For each module record:
- stable module ID and original repository/path
- version/commit and content digest
- purpose, inputs/outputs, dependencies and interfaces
- permission and data boundary
- tests, benchmark command, observed results and evidence grade
- conflicts/duplicate implementations and historical lineage
- integration status: DISCOVERED, INVENTORIED, ADAPTER_DEFINED, INTEGRATED, TESTED, VERIFIED, BLOCKED

### 3. Use CONZETIAN-AI + omega-10 + Phoenix as the first vertical slice
Target flow:
approved artifact ingestion → provenance-preserving retrieval → inspectable structured plan → explicit permission gate → bounded tool action → independent output verification → signed append-only receipt → reproducible export.
Keep the first run local and use synthetic/public non-sensitive input. Never require API credentials merely to pass the core local tests.

### 4. Connect skills and domain systems through adapters
Load skill files as data/instructions under a permission boundary. Add adapters for ZAAI scroll modules, CZAOUA components, OmniNet routing, We-Ω dyad, MAIA/IIA modules when their exact repository paths and interfaces are discovered. Preserve names and semantics; do not invent expansions for acronyms that the source does not define.

### 5. Prove Source and Supermesh incrementally
First define the Source contribution envelope and recipient inbox. Then prove two-node authenticated exchange and user-controlled accept/decline. No private workspace content propagates by default. Contribution distribution is global; adoption is individual.

### 6. Execute test suites and keep a friction ledger
Run the actual declared test commands in an available environment. Classify each failure, repair only the narrow cause, re-run the failed test and regression suite, and record receipts. If execution is blocked, record the exact blocker and continue with independent tasks.

## Goal completion gates
The first meaningful milestone is one clean, reproducible, end-to-end run that includes a real module from the existing repository ecosystem. The next is an independently started second node. The broader goal is met only when a clean environment can:
1. load a user's authorized Source Block configuration;
2. use their Source Bot to capture an intent;
3. preview and authorize a Conzitionware plan;
4. execute through Phoenix;
5. verify output independently;
6. record a tamper-evident receipt;
7. package an attributed contribution;
8. distribute it to a second node;
9. allow the recipient to accept, defer, or decline;
10. reproduce the complete trace and recover from injected faults.

No percentage is assigned without a defined denominator and passing evidence for each gate.
